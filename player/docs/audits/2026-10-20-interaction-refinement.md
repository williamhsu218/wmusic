# WMusic 1.0.8 交互修整

依据用户提供的 `wmusic优化方案.md`，继续检查 1.0.7 的六项交互问题。文档中的问题描述作为待核实线索，末尾的提问不作为用户指令。

## 实现与取舍

1. **专辑头部**：使用实测展开/紧凑高度差加 64 点余量决定收起，回到顶部才展开；过滤视口高度变化引发的偏移回调。短列表没有足够滚动空间时保持展开，避免头部收缩后列表被钳回顶部的反馈。保留离散收起，没有引入逐像素插值。展开/紧凑的 Play、Shuffle 使用同一专辑入口，空曲目时均禁用。
2. **封面墙**：播放圆钮默认完全隐藏，整张卡片悬停或按钮键盘聚焦时显示。封面、标题和播放入口统一检查当前点击事件的 Command 修饰键；保留多选、键盘导航和辅助功能播放操作。
3. **播放展示**：去掉预热隐藏层与底栏封面的共享几何来源切换，采用局部缩放和淡入淡出；进度预览放在原时间标签，不再浮到播放按钮上。沉浸模式增加留白及明确的退出按钮，主窗口展开页继续使用收起按钮。
4. **统一侧栏**：全局坐标拖拽，宽度限制 260–420 点，增加拉伸光标、可读宽度和每次 20 点的辅助功能调整。嵌入歌词去掉重复标题与材质，保留字号、来源、偏移、搜索及编辑；队列增加沿用原确认流程的清空入口；音频参数自动换行紧凑排列。
5. **曲目表**：只在当前/刚失去播放状态的单元格更新指示器，复用时停止隐藏动画。高亮采用内缩圆角及胶囊标记，刷新跟踪区域并在窗口失焦时清除悬停。
6. **启动扫描**：明确注册默认关闭值。已有曲库的用户选用启动扫描允许正常退出；首次建库、计数未知、手动扫描和 ReplayGain 分析继续保留退出保护。启动扫描在建立任务前同步确定首次建库状态，避免刚启动就退出的竞态。

## 验证方法

- 最终 UI 回归 1,187 项、211 个测试套件通过；10 项受影响快照、5 个套件通过。改动的 20 个 Swift 文件通过 SwiftFormat 0.63.0 检查，AppKit 引入审计通过。
- 独立 Bundle ID、合成音频及独立数据库验证，不以真实曲库播放作为测试。
- 同一候选与重签名 QA 应用比较 51 个代码/数据区段；签名、沙盒与候选版本另行核对。
- 原生界面检查短/长专辑滚动、Command 点击封面和标题、键盘打开、歌词定位、清空确认、侧栏拖拽与调整、展开返回及沉浸退出。
- 原生验收发现两个额外回调问题并补测：队列执行前 AppKit 已调整 bounds 时不应丢弃真实滚动；滚动条出现只改变宽度时不应吞掉首轮纵向输入。
- 保留初次失败及修复后证据。最初并行重构建时有两项播放显示时序测试失败，隔离及后续串行全量运行通过。一次过宽快照筛选还命中了两个未改动 MiniPlayer 高对比度基线差异；未重录这些无关基线，也不宣称全快照集通过。

## 边界

原方案对旧版抖动与 Command 冲突的所有描述没有全部原生复现；改动同时依据代码、边界测试与实际界面验收。没有用截图宣称逐帧动画性能已量化；减少动态效果分支保留且有代码/测试证据，没有切换系统设置验证整个动画。真实 NAS 断线重连、其他 Mac 和 Intel 安装未纳入本轮验收。

本机详细证据位于 `.build-logs/interaction-ux-20261020/`；公开版本边界及最终交付结果见仓库根目录 `VALIDATION.md` 和 `docs/releases/v1.0.8.md`。
